# Pane groups and the stash session

A section of [TMUX-TAGS.md](TMUX-TAGS.md), which holds the tag schema these options belong to.

Pane groups are **not** a window type. A group is a set of panes sharing a `@tmuxy-group-id` pane option, minted from the anchor pane id (`%5` → `g5`) and unique for the group's life because tmux never reuses pane ids. The **visible** member is an ordinary pane in the attached session; the **hidden** members are parked one-per-window in a dedicated session, `__tmuxy_stash`, which is never attached and is filtered out of every session enumeration (the sidebar tree, `session switch`, the server picker).

Because a pane's options travel with it across a **cross-session `swap-pane`**, switching group tabs moves the target member into the visible slot and the previous one into the stash with no membership bookkeeping — verified behavior on tmux 3.7.

The group rules live once, in `tmuxy_core::groups`: pure functions that take the members read from one `list-panes -a` and return the tmux command list for each operation (add, park, close, switch, next, prev, move, join, leave, gc). That one read is a `list-panes -a -F` whose fields are separated by a **space**, the session name last: tmux 3.4 prints a control character in a format as `_`, so a tab-separated row would arrive as one field. The `group` verb (`tmuxy-verbs/src/group_cli.rs`) runs them from inside `run-shell`, the same safe path the session CLI uses, and answers under the CLI's contract (`--json`, the exit codes); the `packages/tmuxy-cli/bin/tmuxy/pane-group <verb>` script is a thin wrapper around it, so its name and arguments (which the UI, the key bindings and snapshot restore call) stay put, and `tmuxy pane group` forwards its words to that script. A member's `pane-died` hook names the `pane-group` in the data dir's scripts directory (`Layout::scripts`), whether the member was made live or by a restore. The script finds the verb where the CLI finds every Rust verb (`find_server_cmd`): the server binary named by `TMUXY_SERVER_BIN` / `TMUXY_SERVER_SUBCOMMAND`, which every tmuxy process publishes to its tmux server's global environment on attach, then `tmuxy-server` on `PATH`, the repo's `target/`, the desktop launcher, and last the `tmuxy-verbs` binary the in-browser guests ship in place of a server. The stash session is created lazily (`new-session -d -s __tmuxy_stash`, control-mode safe). Closing a member sweeps orphaned stash members, and so does each add; a tab close (the UI's `kill-window`, the CLI's `tab kill`) runs the same sweep (`gc`) in its own command list, since a killed window's parked members get no `pane-died` of their own. Should a sweep still be missed, the orphans are invisible: the backend prunes any stash member whose group has no visible pane from the emitted state, so an orphan never renders as a phantom tab.

A group's **order** is `@tmuxy-group-pos` on each member, ascending, with members that carry none after them in pane-id order — so a group nobody rearranged reads in creation order, and the backend (`groups::order_key`, also used by snapshots) and the client (`groupMembers` in `tmuxy-ui/src/domain/client.ts`) apply the same rule. `nav` steps between members with `group next|prev --no-wrap` (exit 3 means no member that way, and the step falls through to the neighbouring pane or sidebar). Move, join and leave rewrite every member's place 0..n-1. `join` breaks the pane out of its window into the stash like a new member; `leave` first hands an on-screen member's slot to the next member in order, then moves the pane out as a tab of its own (`move-window` of its stash window) or splits it in beside a target (`join-pane`), and a group left with one member stops being one. None of these produce a notification tmux sends for options, so each ends by bumping the global `@tmuxy-group-rev`, which the monitor's pane-metadata subscription sees within a second. The order is saved with the session snapshot (a visible member's place as a pane option, a parked member's as its `position`) and restored by `pane-group park`.
